@/docs/golden-principles.md

Always apply the golden principles above to every task in this project, regardless of size.

Read @README.md before every change. It is the entry point that describes the current state of the
project, the tech stack, the setup, and the workflow. Do not start work — not even a small edit —
without having read it in the current session.

Keep @README.md up to date. It must always describe the project as it actually is right now, not as
it was planned. Whenever a change makes a statement in the README wrong or incomplete (new setup
step, new command, changed stack, a feature that now exists, a section marked "noch anzulegen" that
now exists), update the README in the same change. An outdated README is a defect, not a follow-up
task.

For every larger change (anything beyond a small, self-contained edit), write an execution plan
first, following @docs/PLANS.md. Do not begin implementing a larger change until the
plan exists and is self-contained per PLANS.md's requirements.
The Plan should be written so that a Junior Engineer can execute the Plan. Plan the milestones granular.
Keep yourself concise.
